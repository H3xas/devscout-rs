The enriched lane continues with the remaining commands of
[`bench/semantic-enriched.sh`](../../../bench/semantic-enriched.sh): the oracle in
`--emit compiler-facts` mode (`--tfm net9.0 -p Configuration=Debug -p Platform=AnyCPU`, plus the
forwarded `-p:TargetFrameworks=net9.0`), `devscout compiler-facts import`, `devscout map .`, and
both audits again against the same `refs.jsonl`/`units.jsonl`. It runs in three passes:

1. **Audit-off pass**, the one the enriched tables come from: a fresh copy restored with
   `-p:TargetFrameworks=net9.0 -p:NuGetAudit=false`, the flag passed to the restore, the oracle
   and the compiler-facts run alike, as in the 0.8.0 run.
2. **Audit-on pass**: the oracle's own copy, restored without that flag, so offline NuGet's
   vulnerability audit logs `NU1900` for each project; this tree's producer, then the same
   import, map and audits.
3. **All-partial artifact**: on the same audit-on copy, the 0.8.0 producer (which still demotes a
   compilation on `NU1900`) writes an artifact in which no counted compilation is complete; this
   tree's `devscout` imports it, maps and audits. This is the case of an artifact produced before
   the upgrade, which keeps its states until it is produced again.

The scorecard runs from the bench root with its own copy at `bench/corpora/csharp`, as in 2026-08
and both earlier release runs, and never sees a compiler-facts artifact. The rebuilt 0.8.0 binary
answers the same cells on a copy of its own, for the grading rule below.

## What this measures / does not measure

- **Default lane, resolver precision**: the same figures, tables and pins as the 0.8.0 run, with
  the metric definitions, join rule and exclusions of
  [`methodology.md#resolver-precision`](../methodology.md#resolver-precision). `audit` scores
  `uses-member` edges only, so `bus-hop` edges stay **excluded** from every precision and recall
  figure. Every figure that differs from the 0.8.0 run is attributed: the two graphs are compared
  edge for edge, and every precise wrong-target row that leaves is matched to its mechanism in
  [`bench/precise_wrong_target_rows.jsonl`](../../../bench/precise_wrong_target_rows.jsonl).
- **Bus-hop reach**: the 0.8.0 run's reach table, re-measured: edges, messages, publish sites,
  handlers, evidence words, and the share of the one shared test message. Reach only; route
  precision and recall stay unmeasured.
- **Enriched lane (opt-in)**: the 0.8.0 run's enriched tables and registered gate at this tree,
  against a freshly produced and freshly admitted artifact, plus what the lane record and the
  audit label now print for each of the three passes. Like Runs 7 and 8 and the 0.8.0 run, this is
  **consumer conformance only**: both lanes are scored against the same oracle output, not against
  independently verified truth.
- **Scripted scorecard**: the eight tasks of [`2026-08.md`](2026-08.md) (L1, L2, R1, R2, I1, I2,
  E1, E2) with the same commands, corpus pin and grading as the 0.8.0 run, for the arms devscout
  (this release, default lane), `rg` (skilled) and `ast-grep` (R1/R2 only).
- **Not measured**: the agentic (model-in-the-loop) round, which stays the preliminary 0.2.0
  measurement of 2026-08; the TypeScript and Rust support this release adds (measured on their own
  corpora in [`2026-10-11-typescript-reference-parity.md`](2026-10-11-typescript-reference-parity.md),
  [`2026-09-27-rust-edges.md`](2026-09-27-rust-edges.md) and
  [`2026-10-03-rust-targets.md`](2026-10-03-rust-targets.md); this corpus holds no `.rs`, `.mjs`,
  `.cjs`, `.mts` or `.cts` file and six `.ts` files); the peer roster beyond `rg` and `ast-grep`;
  any corpus other than the pin; repeat variance.

### Enriched lane (opt-in)

Basis, besides (b), (c) and (e):

- **(g)** The producer keeps a workspace diagnostic out of a compilation's state when the
  project's own assets file logs it as `NU1900` to `NU1905` at `Warning` level with the same
  message. In the 0.8.0 run's audit-on pass every loaded compilation was demoted
  `partial`/`workspace-failure` by exactly such a diagnostic (56 of its 62 workspace diagnostics
  were `NU1900`), apart from the one `binding-error` compilation.
- **(h)** The lane record counts a compilation whose state is `complete`, `partial` or `failed`;
  `unsupported` and `excluded` are not counted. With no counted compilation complete, `map` drops
  the artifact before resolution (`not-applied`, `no-complete-compilation`); with some counted
  compilation not complete and something confirmed or discovered, the record is `partial`
  (`compilations-incomplete`) and `audit` reports `enriched-partial`. The detail reads
  `K of M compilations partial: <reason> <n>, ...`, reasons in byte order.
- **(i)** A same-context fact overrides whatever the syntax ladder answered at its site and counts
  as `confirmed` either way; `disagreements` counts only the overrides whose ladder target
  differed. Fixes to the ladder therefore leave the `semantic` row alone and can only lower
  `disagreements` where they now agree with the compiler. References no fact covers keep the
  ladder's answer, so the residual `precise`/`ext`/`guess` rows inherit the fixes.
- **(j)** The compiler diagnostics in compiler-facts output are now in one fixed order, the only
  difference the 0.8.0 run found between repeated artifacts.

### Scripted scorecard

What this release changes in the scorecard's devscout answers:

- **The count line and the next verb.** The count line goes to text and `--compact` output of
  `refs`, `read`, `impact` and `tests`, which no scorecard cell uses. The next verb reaches every
  devscout cell: `find` text (L1, L2, E1, E2) gains a final `next:` line, and the `refs` and
  `impact` `--json` answers (R1 and its plain form, R2, I1, I2) gain a `next` array. Neither can
  change a grade: the grader reads file rows from `find` and `sites`/`inbound`/`rows` from the
  JSON, the trailer begins `next:` and matches neither row pattern, and `next` holds argument
  vectors, not rows. Every devscout cell grows in bytes.
- **Resolver output.** A fix that moves an edge an answer reads changes that answer beyond the
  additions. Most exposed: the hop-2 tails of I1 and I2; R2's three files that reach `IJobService`
  members through a property typed with it, since three of the fixes act in the property hop; and
  `find`'s ranking, which reads inbound counts.

### Scorecard grading

The 0.8.0 run's registered rules, unchanged, with the previous release as the reference run:

- **References.** Core set = the files naming the symbol as a whole word, minus its declaring
  file (R1 18 files, R2 8). `correct` at ≥75% of core with ≤2 files outside core ∪ admissible
  (the declaring file is admissible); `partial` at ≥40%.
- **Impact.** Graded set = the seed's hop-1 dependents (I1 the 8 files of R2's core, I2 the 5
  files naming `IntervalRetryPolicy` beyond its declaring file). `correct` needs every graded file
  within the declared cap of 5x the graded set (40 and 25 rows); `partial` needs at least half.
- **Locate and e2e-retrieval.** `correct` names the primary file (`MessageUrn.cs`,
  `IntervalRetryContext.cs`, `InMemoryOutboxFilter.cs`, `BusHealthCheck.cs`). An output that omits

  has the byte count that run published. Before any 0.9.0 cell is graded, the grader is run over

- **Reach**, bytes (`tokens = ceil(bytes / 4)`), cold and warm-median-of-5 wall time, and tool
