# TypeScript module resolution comparison

## Registered inputs

The public fixtures, exact commits, licenses, directory prefixes, modes and minimum truth-resolvable counts are in `fixtures.json`. `bench/corpus.lock` pins the same commits. The selected prefixes each have at least 100 truth-resolvable imports in the preflight and at least 20 individually. Synthetic repositories under `fixtures/module-resolution/` cover the negative cases and manifest shapes absent from a qualifying public fixture. The first registration under `bench/truth/module-resolution/` and its `2026-10-15-typescript-module-resolution.md` result remain available; this registration alone judges this comparison.

The implementation base is `f136d8ba30ad5f4d6f80f2c5c60173349abd599c`. The two arms are `devscout-base` built from that commit and `devscout-head` built from the committed head under review. Each runs once on its own pristine copy of every corpus. A code fix creates a new head arm run with its own stored outputs; the registered inputs stay fixed.

## Truth

Use TypeScript 5.9.3 from the local offline npm cache. `bench/ts_resolution_sites.cjs` parses the nearest declaring tsconfig chain for each importer, sets `noDtsResolution: true`, determines import or require usage, and calls `resolveModuleName` for the sites the extractor records: top-level string-literal import and export-from declarations; top-level import-equals with an external string-literal module reference and no export modifier; a direct string-literal `require` initializer in a top-level, non-exported variable declaration; and literal dynamic `import()` calls anywhere. A non-literal dynamic import is listed without a resolution. A nested or exported `require`, a bare `require` call, and a module reference inside a namespace or ambient module are not sites. The line key is the statement start for imports, exports and import-equals, the declarator start for `require`, and the call start for dynamic import. The script overlays workspace members under virtual `node_modules` paths and mapped build outputs without installing dependencies. An implementation target is a repository-relative path only if it is among the indexed TypeScript and JavaScript implementation files. A declaration, external package or unresolved specifier has an empty target. Each row adds form, resolved mode, linked member directory and mapped-output flag to the first registration's five columns.

`expected.tsv` under the synthetic fixtures holds the TypeScript target or one of the resolver's closed unresolved reasons for each recorded site. Both binaries map every synthetic case, and the reason annotations are checked from each graph. Refused configuration is checked separately: TypeScript may tolerate a shape the declared resolver intentionally refuses. The classified truth is produced and hashed before either arm runs.

## Scoring and gate

Each site is keyed by importing file, one-based line and specifier. Before either arm, `bench/ts_resolution_envelope.py classify` reads the fixture and truth only and applies the first matching exclusion in this order: `non-literal-import` for a non-literal dynamic import; `mode-not-declared` when a followed tsconfig chain declares no supported mode or disagrees with the truth's mode; `types-versions` when the entered package declares `typesVersions`; `json-module` for a JSON specifier or resolved path; `refused-configuration` when a package manifest, workspace declaration or build-output tsconfig input used by this site is refused by the documented readers; and `pnpm-default-ignore` for a pnpm member under a default-ignored directory. A site with none is in scope. A site classified `outside-envelope` leaves all agreement, wrong-target and spurious pools, but remains listed with its sub-class, truth and each arm's actual edge. A classifier input it cannot read or a row it cannot classify is an error, never an in-scope fallback.

The classifier reads strict JSON package manifests, JSONC tsconfig chains with relative `extends` (up to four links), and the `packages` sequence of pnpm workspace YAML. It validates `name`, `type`, `main`, `exports`, `imports` and workspace patterns in manifests, and `moduleResolution`, `module`, `customConditions`, `outDir`, `rootDir` and `composite` in tsconfig. A mode-less scope, including explicit `classic`, is excluded. For `types-versions`, the entered package is the linked member or the relative directory manifest. For `refused-configuration`, inputs are the importer's format or self-name manifest where applicable, a linked member's manifest and workspace declarations on the ancestor path, and the mapped member's tsconfig chain when an output mapping was used. For `pnpm-default-ignore`, the member must be selected by the root pnpm workspace and have a `node_modules`, `bower_components`, `test` or `tests` path segment.

For an in-scope site, a direct `import` edge with no `via` is compared with truth. `agree` means the edge names the truth file. `agree-unresolved` means truth names no indexed implementation file and there is no edge. `miss` means truth names a file and no edge exists. `wrong-target` means an edge names another file. `spurious` means an edge exists where truth names no indexed implementation file. Every disagreement is listed in the results file with its class, truth and actual target.

For each mode pooled across its registered public fixtures, agreement is `agree / (agree + miss + wrong-target)` and must be at least 0.95. `wrong-target` and `spurious` must each be zero. Every synthetic positive and negative row must match, including its unresolved reason. Base and head scores are stored separately and rendered together by `bench/ts_resolution_envelope_report.py` into a new dated `typescript-module-resolution-2.md` results file. The renderer names the first results file and lists every excluded site by fixture, arm and sub-class. The registration manifest hashes both registrations, the first results file, the truth script, classifier, scorer, renderers, runner, fixture list, synthetic expectations, this procedure and corpus pins; verification precedes each measured run and score.
