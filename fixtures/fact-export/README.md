# fact-export fixtures

Three small trees, one per language, that between them record every fact family
`devscout export` publishes. They are deliberately dedicated to this contract
rather than shared with the extractor suites: the pinned exports below are
regenerated byte for byte by `cargo test --test fact_export`, and a shared tree
would make another ticket's fixture edit invalidate these pins.

| Tree | What it covers |
| --- | --- |
| `csharp/` | A bus stand-in declared locally (no package reference), a publish matched to a registered handler and one that is not, a handler registration, a dependency registration, a constructor-injected parameter resolved to one implementation and one left unresolved, a partial type declared in two files, two same-named statics reached by an unresolved qualifier, an unresolved `using` target, and two calls to one target on one line. |
| `typescript/` | A `NodeNext` module mode with one specifier that resolves and one that does not, an import, a call, a JSX use and a dispatch, and a `*.spec.ts` file. |
| `rust/` | A real Cargo package: a trait with an implementation, a member call through the trait, and an inline `#[cfg(test)]` module. |

The trees are never built: `.csproj`, `package.json` and `Cargo.toml` exist so
the project model and the module resolver have something to read, and nothing
here is compiled by this repository's gates.

## Test classification

`csharp/` carries two projects so both vouches appear: `Fixture.csproj` at the
root (not a test project) and `tests/Fixture.Tests.csproj`
(`<IsTestProject>true</IsTestProject>`), which places `tests/` in a test
project. `tests/LedgerTests.cs` declares a `[Fact]` method, so it is
attribute-vouched; `tests/LedgerHarness.cs` declares none, so it is
project-vouched. `typescript/src/page.spec.ts` is path-vouched, and
`rust/src/lib.rs` is attribute-vouched through its `#[test]` function.

## Pinned exports

`csharp.ndjson`, `typescript.ndjson` and `rust.ndjson` are the exports of the
three trees, with the header's per-run and per-release values replaced by fixed
placeholders so that a new `map` generation or a version bump does not
invalidate them:

| Key | Placeholder |
| --- | --- |
| `provenance.index.generation` | `"generation"` |
| `provenance.index.indexedAt` | `"indexedAt"` |
| `provenance.source.indexedHead` | `"indexedHead"` |
| `provenance.analysis.devscoutVersion` | `"devscoutVersion"` |
| `provenance.analysis.fragmentGeneration` | `0` |

Only the header line is rewritten; every other byte of every other line is the
export's own, including `analysis.graphSchemaVersion`, `fileCount`, `scope` and
the digest of the digest table. `fact_export.rs` asserts the real values against
the crate's own constants beside the pin, so the placeholder never becomes the
only evidence a version moved.

Regenerate after a change that legitimately moves the recorded facts:

```console
$ BLESS=1 cargo test --test fact_export
```

A regeneration that is not explained by such a change is a defect in the export,
not a stale pin.

## What these trees do not produce

No `ext`-tier edge and no `ambiguous` edge arises on these small trees: the
unresolved qualifier in `csharp/src/Boot.cs` records two name-tier guesses
rather than an ambiguous reference, and nothing here makes the resolver refuse a
bind. Both evidence words are covered by the exhaustive unit mapping over
constructed edges in `src/export/tests.rs` instead, and the per-family counts in
the acceptance suite are read off `graph.json` rather than restated.
