# Architecture

How `devscout` is put together: what each module owns, what it must keep true, and where a
change goes. Read this file before the code. `tools/check-architecture.sh` fails CI when a
module under `src/` has no row here or a row names a module that no longer exists, so the
table below is complete by construction.

## Pipeline

One `devscout map` run flows left to right; every query verb reads what it wrote.

```
walk ─► parse ─► extract ──┐
          │      markup ───┼─► resolve (C#) ─┐
          └── preproc      │   tsgraph (TS) ─┼─► graph ─► query ─► render ─► cli
                           │   rsgraph (Rust)┘                             │
                           └───────────────► manifest ─────────────────────┘
project ─► resolve        repo / initcmd / mapcmd / store / hookio / suggest / audit / offsets
```

- **Indexing** (`map`): `walk` lists files, `parse` and `preproc` turn C# into a syntax tree,
  `extract` and `markup` turn the tree into per-file fragments, `resolve` / `tsgraph` turn
  fragments into a graph, `rsgraph` appends Rust definitions and the edges its module tree and
  `use` scope resolve after the resolve,
  `graph` persists it, `manifest` persists the file-purpose index.
- **Querying** (`find`, `refs`, `read`, `impact`, `tests`): `query` builds an in-memory index
  over the persisted graph and answers; `render` formats; `cli` parses arguments and returns
  `(exit code, output)`.
- **Agent integration** (`init`, `hook`): `initcmd` installs hooks and registers the repo,
  `hookio` rewrites tool results, `store` keeps the freshness caches.
- **Measurement** (`audit --semantic`): `audit` scores `uses-member` edges against an
  oracle export.

## Modules

One row per file under `src/`. Invariants are the facts the rest of the crate relies on;
breaking one is a behaviour change even when every test still passes.

| Module | Responsibility | Invariants |
| --- | --- | --- |
| `src/lib.rs` | Crate root: declares every module (including `rsgraph`) and documents it in one line. | Every module under `src/` is declared here with a one-line doc. |
| `src/main.rs` | Binary entry point. | Hands `std::env::args()` to `cli::dispatch` and does nothing else. |
| `src/audit.rs` | Root of `audit --semantic`: the module header (join rule, split rationale), the `mod` list and the public re-export. | Holds no code. The public surface is `cmd_audit`; every other item is `pub` at most within `audit`'s own module tree. |
| `src/audit/model.rs` | The shared row/`Inputs` shapes: `Tier`, `EdgeRow`, `DefRow`, `OracleRef`, `Unit`, `Inputs`, `AuditOptions`. | No I/O and no scoring logic; every field is `pub` within the crate so the sibling modules below can read it directly. |
| `src/audit/load.rs` | Filesystem reads: `load`, `parse_graph`, `read_jsonl`, `tier_of`, `build_universe`; the lane comes from `lane.rs`. | Returns a plain `String` error, the shape every `cmd_*` in `cli.rs` wraps as `"error: {msg}"`. `graph.json` is read as a bare `serde_json::Value`, never through `graph::read_graph`. |
| `src/audit/lane.rs` | The lane `audit` reports: `AuditLane`, its `read` from graph.json's `stats.lane`/`stats.semantic`, the text header token and the `lane_detail`/`compilations` JSON keys. | `enriched-partial` when `stats.lane.state` is `partial`, else `enriched` when `stats.semantic` is present, else `syntax`. A graph without `stats.lane` reads, renders and gains no key exactly as before; the header names the partial or not-applied reason only when the record carries one. |
| `src/audit/scoring.rs` | Pure matching/structural-check primitives: `target_matches`, `member_matches`, `target_known`, `short_name`, `file_to_unit`, `reach`, `is_structural`. | No I/O. `target_matches`/`target_known` both apply the enum-member two-spelling allowance identically. |
| `src/audit/report.rs` | `TierStats`, the per-tier counters `score.rs` fills and `render.rs` reads. | `structural` counts false positives only, never a structurally-impossible true positive. |
| `src/audit/score.rs` | `AuditReport` and `score`: the pure `Inputs -> AuditReport` scoring pass, including the `--fp-sites` row collection when `Inputs.collect_fp_sites` is set. | Pure: every branch reads only `Inputs` and locally built indexes over it. Oracle records are joined to edges by site (file and line), target and member; a `partial file mismatch` only affects the file join of true positives, never precision. |
| `src/audit/render.rs` | Text (default) and `--json` rendering: `render_text`, `render_json`, `ratio_text`, `ratio_j`. | A zero-edge tier row is omitted, never printed as zero. |
| `src/audit/assert_check.rs` | `--assert <file>` threshold evaluation: `evaluate_assert`, `lookup_metric`, `fmt_num`. | Collects every violated or missing key before returning, never stops at the first. |
| `src/audit/fp_sites.rs` | One row per false positive written by `audit --fp-sites <file>`, built inside `score.rs`'s own scoring loop from the same evidence set that decided the edge's class. | Built only when `Inputs.collect_fp_sites` is set; the row count of one class and tier always equals exactly that tier's counter for the class, by construction. |
| `src/audit/cmd.rs` | `cmd_audit`, the CLI entry point `cli.rs` dispatches `audit` to. | Reads the graph read-only. `--json` keeps `--assert` violations on stderr so stdout stays one parseable JSON object; text mode appends them to stdout. With `--json` anywhere in the arguments every error also goes to stderr and the returned output is empty, which the `audit` dispatch arm does not print. `--fp-sites <file>` writes `fp_sites.rs`'s JSON-lines rendering independent of `--json`/`--assert`. |
| `src/audit/tests.rs` | Shared fixture builders for the audit tests (`fragments_for`, `graph_value_for`, `oracle_ref`) and the `mod` list for the nested test files. | Builds `graph.json` through the real extractor/resolver, never a hand-written `Value`, so no test bypasses the parse path. |
| `src/audit/tests/scoring.rs` | Matching, leak and structural-impossibility scoring cases. | One case per named scoring rule in `scoring.rs`/`score.rs`; every case builds its graph through `tests.rs`'s real-extractor helper. |
| `src/audit/tests/render.rs` | The three rendering-pin cases (`--assert` pass/fail/missing, JSON key order, text layout) plus the fixture-backed `--assert` tests. | Pins the exact text/JSON shape `render.rs` promises; a key-order or column change must update these tests deliberately. |
| `src/audit/tests/semantic.rs` | The audit lane over hand-written `stats` blocks: the label, the text header token, `lane_detail`/`compilations`, their key position, and `--assert` over `compilations.partial`/`compilations.total`. | A graph without `stats.lane` is pinned to render with no new key, so a report from before the lane record reads the same. |
| `src/cli.rs` | Root of CLI dispatch: the module overview, the `mod` list and the public re-exports. | Holds no code. The public surface is `dispatch`; `require_repo` stays `pub(crate)` so `audit.rs` can resolve its repo root the same way every command here does. |
| `src/cli/admin.rs` | The `map`, `stats` and `clear` commands: the index build, the cache-dedup summary, and the three prune forms. | `map` prints its summary line and, when the rebuilt graph carries a `stats.lane` record, the lane line after it. None of the three read the graph. `clear`'s whole-store form never opens the store just to remove it; `--older-than` and `--session` are checked in that order, so the first one present wins when both are given. |
| `src/cli/answer.rs` | The answer shape every verb funnels through: the zero-hit exit code and its stderr note, the freshness warning, the two ambiguous-outcome renderers, the not-found fallback, the `--json` `freshness` splice, and the one telemetry call a resolved query makes. | `EXIT_NO_RESULT` (3) is the one code that means a resolved, empty answer, distinct from failure (1) and a usage error (2). An ambiguous type and an ambiguous member answer under the same JSON keys from two different renderers, so a caller branching on `outcome` never has to tell the two apart. `finish_query`'s `json` flag gates `append_freshness`, which splices `freshness` (from `freshness::index_freshness_state`) onto the answer as its true last key on `refs`/`read`/`impact`/`tests`; `find` has no `--json` shape and always passes `false`. |
| `src/cli/args.rs` | Argument-parsing primitives shared by two or more verbs: the bare-query scan, `--pick`, the lenient `--hops`-style integer parse, `--no-guess`, and the `--json`/`--compact` conflict check. | `parse_int_js` accepts trailing garbage after the longest leading digit run (`"3abc"` parses to `3`); `parse_pick` does not -- a bad `--pick` value is always a usage error. `--no-dispatch` and `--no-bus` are parsed in `index_options` exactly the way `--no-guess` already is, on all four verbs. |
| `src/cli/compiler_facts.rs` | The `compiler-facts run|import|status` verb group: local one-shot engine acquisition, build/CI-artifact import, and read-only status. | `run` and `import` converge on the identical `graph::admit_and_publish` call -- the one admission path for both producers. `status` never opens `graph.json`, reports `coverage: syntax-only` when no artifact was ever admitted, prints `coverage: complete` only when no unit is incomplete and every counted compilation is complete (otherwise `partial (K of M compilations: <tally>)`, or the `incomplete (...)` wording with the tally appended), and reports occurrence coverage (admitted count, non-confirmed states, an explicit unavailable state) by an independent read-only parse of the already-admitted bytes. `run`'s own wrapper omits `--capabilities` entirely when the caller passed none, so the spawned engine's own default (not a second, stale definition here) decides. |
| `src/cli/coverage.rs` | The `tests` verb -- tests reaching a symbol. Named `coverage`, not `tests`, to avoid colliding with this module's own `#[cfg(test)] mod tests`. | Mirrors `refs`' own check order and ambiguity handling exactly; only the resolved arm's renderer and JSON builder differ. |
| `src/cli/dispatch.rs` | Top-level argument dispatch: `--help`/`--version`, the four dev/diagnostic subcommands, and wiring each verb's return value to stdout/stderr and the process exit code. | `init` dispatches through `initcmd::cmd_init_full`, never `cmd_init` directly. `hook read`/`hook bash` always exit 0 -- a broken scout must never break the tool call it is post-processing. |
| `src/cli/find.rs` | The `find` verb: the manifest search plus the declaration block a code or markup name resolves to. | The declaration and manifest pools are capped and ranked independently (`FIND_NAMES_CAP`, `FIND_FULL_CAP`, `FIND_FALLBACK_CAP`); tier 3 (a resource key) is a one-line trailer by default, inline only under `--resources`. |
| `src/cli/impact.rs` | The `impact` verb: its own numeric flags (`--hops`, `--iface-max-fanin`, `--hub-max-indegree`), a file-or-symbol seed rewritten repo-relative, and the blast-radius answer. | A resolved seed that reaches nothing beyond its own files is a zero hit, the same signal an unresolved seed gets. |
| `src/cli/import_edges.rs` | The `import-edges` verb: validates a cross-repo edge export and writes the auxiliary artifact `impact` reads. | `--repo <id>` is required and never inferred. A refusal (exit 1, naming the offending value) never calls the writer -- `write_imported_edges` is reached only once parsing already returned `Ok`. |
| `src/cli/read.rs` | The `read` verb: a declaration span layered on `refs`' own resolution. | Every outcome but the resolved one -- not-found, ambiguous, member-ambiguous, the bare-member answer -- is `refs`' own renderer, unchanged; only the resolved arm adds the span. |
| `src/cli/refs.rs` | The `refs` verb: usage text, argument parsing, and the outcome-to-answer mapping every result shape renders through. | `member_models_out` and `refs_model_row_count` are shared with `read`, whose own bare-member answer is refs' own. |
| `src/cli/root.rs` | Repo-root and graph-artifact resolution shared by every verb: the cwd a command runs from, the `.scout`/`.git` ancestor climb, the `-C` global flag, and the mapped `graph.json` every graph-reading verb needs. | `require_repo_for_path`'s argument-named-file fallback only applies once the caller's own directory has come up empty; `-C` composes on repeat exactly as git's does. |
| `src/cli/tests.rs` | Shared fixture builder for the CLI tests and the list of test topic modules. | `json_refs_model` is the only builder shared across more than one topic; everything else lives local to the topic file that uses it. |
| `src/cli/tests/admin.rs` | `js_math_round` and `js_float_string`'s rounding/formatting parity, and every `clear` form: whole-store, `--older-than`, `--session` (unique, ambiguous, no-match, missing-value), and the flag-precedence order. | Pins that a rejected `--older-than` value creates no store, and that `--older-than` wins when both flags are given. |
| `src/cli/tests/answer.rs` | The `J` JSON encoder's object/array whitespace and string escaping. | Pins the exact escapes and that no extra whitespace appears, matching `JSON.stringify`. |
| `src/cli/tests/args.rs` | `parse_int_js`'s lenient-integer parity with `parseInt`. | Pins that trailing non-digit garbage is dropped rather than rejected, and that a leading sign with no digits is `None`. |
| `src/cli/tests/coverage.rs` | `tests_model_to_json`'s `via` placement -- appended last and omitted on an attribute row -- and its `schema_version` lead. | Pins that a project-vouched row carries `via` but an attribute row carries none at all. |
| `src/cli/tests/find.rs` | `cmd_find`'s output caps, its zero-hit exit code, tier-1/2/3 handling, and the declaration-block-above-manifest-block ordering, built through the real extractor and resolver rather than hand-authored JSON. | Pins that a resource-key-only match brakes by default and that a manifest row with no declaration falls back to line 1. |
| `src/cli/tests/impact.rs` | `impact_model_to_json`'s key order: `heuristicCount` then `heuristic` after `score`, `tier` between `heuristic` and `ifaceVia`, and `heuristicAffected` after `manifestGap`. | Pins that every appended key is omitted, not merely empty, on a precise row. |
| `src/cli/tests/read.rs` | `read_model_to_json`'s `span` placement. | Pins that `span` sits immediately after `kind`, unmoved by the `schema_version` key gaining the lead. |
| `src/cli/tests/refs.rs` | `refs_model_to_json`'s and `member_refs_to_json`'s key order and omission rules: `heuristic`/`tier`/`source` appended last, the `outbound` table gated on `--out`, and the member wrapper's own envelope. | Pins that a precise row carries no trace of `tier` and that a member entry inside the wrapper is the resolved object unchanged. |
| `src/extract.rs` | Root of C#, TypeScript-family and Rust extraction: the `mod` list and the public re-exports. | Holds no code. The public surface is `extract`, `run_extract_dump`, `extraction_to_json`, `ts_extraction_to_json`, `extract_ts_file`, `extract_ts_fragment`, `TsFileExtraction`, `extract_rs_file`, `RsFileExtraction`, `RsFragment`, `RsItem`, the `TsFragment` record types, `compose_hybrid_ts_purpose`, `extract_ts_purpose`, `extract_ts_purpose_with_heuristic`, and the C# data model (`DefRecord`, `Extraction`, `ExtensionMethod`, `Fact`, `LambdaSlot`, `NameRecord`, `RefRecord`, `RegistrationRecord`, `UsingRecord`); every other item is `pub(super)` at most. |
| `src/extract/text.rs` | Tree-sitter/text primitives shared by the C# and TypeScript-family extraction: node text, declared names, namespace-level type discovery, and the truncated one-line purpose signature. | `truncate` counts UTF-16 code units, not bytes; `MAX_PURPOSE` (200) is the one limit both language extractors truncate to. |
| `src/extract/types.rs` | The C# data model extraction produces: `DefRecord`, `ExtensionMethod`, `RefRecord`, `RegistrationRecord`, `UsingRecord`, `Extraction`, `NameRecord`, `Fact`, `LambdaSlot`, `PublishRecord` (now also `arg_count` and `enclosing_call: Option<EnclosingCallFact>`), `EnclosingCallFact`. | Plain data, no logic. A `Fact` carries the declared type name plus its top-level type arguments, and two facts agree only when both halves do. A `LambdaSlot` records where an untyped lambda sits so the resolver can type it. A `RegistrationRecord` carries its two type arguments' raw text verbatim; splitting a dotted name into a resolvable pair is the resolver's job. `PublishRecord.arg_count` is the call's own argument count; `enclosing_call` is set only when the call sits inside a lambda body that is itself an argument of an enclosing invocation. |
| `src/extract/refs.rs` | Building `RefRecord` candidates -- `push_ref`, `push_ctor_param_ref`, `push_member_ref`, `record_single_type`, `record_base_list` -- the type/generic-descriptor primitives that feed them, and `registration_fact`, the two-type-argument DI registration shape rule. | A member-access qualifier's `generic` flag is type-certainty syntax only a type can carry; `receiver_type` is set only for a bare, non-generic qualifier. `registration_fact` fires only for an invocation whose generic method name begins `Add`/`TryAdd` and ends `Singleton`/`Scoped`/`Transient` and carries exactly two type arguments; every other shape (one argument, a non-invoked method-group reference, an unmatched name) records nothing. |
| `src/extract/members.rs` | Raw per-member fact extraction for one type declaration: methods, properties, fields, bases, extension methods, arities, parameter descriptors, test methods, `override`-marked method names. | No accessibility filter on properties or fields; `methods` and `non_public_methods` partition method declarations with no overlap and no gap. `raw_override_method_names` draws from the same method population `raw_method_arities` does, so an override's own arity fact is read off that one table. |
| `src/extract/type_defs.rs` | Assembling `DefRecord`/`NameRecord`/`UsingRecord` instances from the raw member facts: `record_type_def`, `record_enum_members`, `record_declared_members`, `record_using`, `type_id`. | Nested-type ids join with `+`, never `.`; an enum member's id appends `.` even under a nested type. |
| `src/extract/type_arity_facts.rs` | Type-parameter and type-argument counts: a declaration's own type-parameter count, each method overload's count aligned with `raw_method_arities`, and the length of a type-argument list written on an invoked member. | `raw_method_type_arities` walks and skips exactly the declarations `raw_method_arities` does, so position k of both lists is one overload. A written list is counted by its direct commas, so a nested argument's own commas never count; a member written without a list records nothing. |
| `src/extract/type_param_sites.rs` | Where each overload's own type parameters occur in its parameter types (`methodTypeParamSites`), and a delegate's return and type-parameter occurrences (`delegateSignature`). | Walks exactly the declarations and parameters `raw_method_params` walks, so the sites line up with the descriptors overload for overload and parameter for parameter; a site names the top-level type argument it sits in after one `Expression<...>` wrapper, or -1 outside every type argument. |
| `src/extract/bus.rs` | Message-bus publish-site facts (`publish_fact`), the nested base type-argument fact a generic consumer base needs (`nested_base_type_args`), and the array-marked subset of a def's own base names (`array_message_bases`, position 0 of a base's type-argument list an `array_type` node); also the call's own argument count (via `refs::invocation_arg_count`) and `enclosing_call_through_lambda`, which walks UP from the call to an enclosing lambda ancestor and one level further to that lambda's own parent invocation. | `publish_fact` resolves a message from a generic type argument, a constructed type (direct or nested in a lambda argument, `object_creation_expression` or `array_creation_expression` alike via `Construction::Typed`), an implicitly typed array creation whose elements all construct the same type (`Construction::ImplicitArray`, `implicit_array_message`), or a plain identifier's declared type read through the ordinary scope ladder -- appending `[]` when `Fact::is_array` says the identifier's own declared type was an array -- never from a bare name merely co-located on the same source line. A message the call writes keeps its written qualifier (`written_message`: `new Ns.M()` records `Ns.M`, `new Ns.M[n]` records `Ns.M[]`), the same segments the site's own type reference records, rebuilt from the qualifier's own tokens with whitespace, comments and other trivia between them left out on every call shape (type argument, construction, explicit and implicit array), so the resolver's last-dot split always sees `Ns.M`, and reads it through the qualified steps; `type_descriptor` itself, shared with method parameters and consumer bases, still drops it, and an identifier argument's message keeps its receiver fact's bare name. A message the call NAMES itself is recorded whatever the method is called, since which verbs count is settled at resolve; the identifier shape alone stays gated on the shipped verbs, being far too common to record everywhere. A message that is the enclosing method's own type parameter records that method's name instead, which is what marks a forwarding wrapper. `nested_base_type_args` records an entry only for a base carrying a top-level type argument that is itself generic; a flat base contributes nothing new beyond `base_generic_args`, which is what `array_message_bases` exists to recover the array bit for, since `base_generic_args`/`generic_arg_descriptors` look through an `array_type` to its bare element. `enclosing_call_through_lambda` is a plain node-kind walk (`lambda_expression`/`anonymous_method_expression` ancestor, then that lambda's own enclosing `argument`/`argument_list`/`invocation_expression`) -- no new tree-sitter query -- feeding the resolver's two structural refusals (see `resolve/bus.rs`) without validating any receiver's own declared type. |
| `src/extract/bus_vocab.rs` | Facts a repository declares about its own message vocabulary: one-type-argument handler registrations (`handler_registration_fact`) and the single type arguments a type's properties wrap (`property_message_args`). | A registration is recognized on an installation-shaped name carrying exactly one type argument, which is the whole discriminator against the two-argument DI registration. Both rules are deliberately permissive: neither decides anything, and the resolver keeps only a registration whose named type carries a generic base and only a property argument on a type it already holds to be a handler, so a loose match here costs fragment bytes rather than edges. |
| `src/extract/receivers.rs` | The local/field fact tables (`FactTable`, `Fact`) a member-access qualifier resolves against: `collect_type_facts`, `collect_member_facts`, `visit_member_facts`. | The member table is flat and shadows the type table; a conflicting or untyped local is stored as `None` rather than omitted, so it never falls through to a same-named field. |
| `src/extract/lambdas.rs` | Untyped lambda-parameter slot typing: `lambda_argument_slot`, `lambda_slot_fact`, `lambda_receiver_element_fact`. | A lambda parameter's type is read positionally off its callee's delegate parameter, never off a fact table directly. |
| `src/extract/delegate_args.rs` | A call argument's own delegate-shaped parameter count: `delegate_argument_param_count`, for a lambda literal (counted from its own parameter list) or a bare identifier naming an in-scope local function, passed as a method group. | A named argument and every other method group -- a type's member, an extension method, an ambiguous or shadowed name -- record nothing rather than a guess; a local function counts only when exactly one same-named declaration is in scope and no nearer lambda, local, or `foreach` variable rebinds the name first. |
| `src/extract/lambda_shape.rs` | A call's per-position lambda-literal shape (`lambdaArgShape`): whether the body can only produce a value, and whether the parameters are implicitly typed. | Value-only is a positive reading: only expression kinds C# can never use as a statement expression, or a block with a `return <expr>;` of its own, count; every other body, including a kind the list does not know, reads as possibly void-compatible. A named argument, a method group and an anonymous method record nothing. |
| `src/extract/qualifiers.rs` | `Scope` and member-access qualifier resolution: `resolve_member_qualifier`, `chain_tail_receiver_type`, `resolve_call_chain_tail`. | `this`/`base` resolve against `type_stack`, never against a same-named local or field. A dotted qualifier never inherits a receiver fact. |
| `src/extract/walk.rs` | The top-level recursive-descent AST walk (`walk`, `walk_list`) and its `pub fn extract` entry point. | `type_stack` doubles as the "inside a type" signal; ref extraction runs at every depth regardless of nesting. A registration fact is checked at every `member_access_expression` that is actually invoked, independent of and alongside the uses-member/uses-type candidates the same call already builds. |
| `src/extract/dump.rs` | The `extract-dump` plumbing verb: `run_extract_dump`. | The only extraction code path that touches the filesystem; dispatches on extension to the C# or the TS-family extractor. |
| `src/extract/json.rs` | Hand-rolled JSON serialisation for both the C# and the TS-family fragment shapes: `extraction_to_json`, `ts_extraction_to_json`. | Matches `JSON.stringify(value, null, 2)` byte-for-byte; no serde dependency. |
| `src/extract/ts_purpose.rs` | TypeScript-family purpose composition: exported top-level declarations, CommonJS and ESM export shapes, re-export bucket segments. | Never builds a def/ref/usings candidate; purposes only. |
| `src/extract/rs_fragment.rs` | Rust item extraction: `extract_rs_file` records every item with its path, kind and span, marks `mod x;` declarations and their `path` facts, tuple and unit structs, test functions (`#[test]` or `test` carried by `cfg_attr`, read by `rs_attrs`) and `impl` blocks, and composes the file purpose, off one UTF-16 parse. | Walks only the file root and inline module, `impl`, `trait` and `extern` bodies; never a function body, an initializer or a token tree. Paths are file-local (`module::Owner::item`), a repeated path takes a `-N` suffix in source order, and no path carries generic or trait text. The declaration facts are keyed by the suffixed path. A readable file always gets a fragment, empty when the parse fails. |
| `src/extract/rs_facts_types.rs` | The Rust resolution facts a fragment carries: `RsImpl`, `RsModPath`, `RsUse`, `RsBlock`, `RsSite`, `RsRole`. | Every field is omitted when empty, so a file with none of the facts serializes as items only. A scope is the inline-module path inside the file; a block index points into the fragment's `blocks`, which holds only blocks with a direct `use`. |
| `src/extract/rs_attrs.rs` | A Rust item's outer attributes in source order, each `cfg_attr` standing for the attributes it carries: `is_test` (`#[test]` or a path ending in `::test`, plainly or carried) and `path_fact` (a `mod x;` declaration's first `path` attribute). | The `cfg_attr` predicate is never evaluated. Inside a `cfg_attr` only an exact attribute form counts, and a malformed `cfg_attr` stands for nothing. A `path` is read only from a plain string literal without escapes or a raw literal; any other value, or a `path` carried by `cfg_attr`, is unread. Nested `cfg_attr` lists unwind on an explicit stack. |
| `src/extract/rs_paths.rs` | Rust path nodes as segment lists (`path_segments`, `join`, `type_path_node`). | Walks a path's nested `path` fields in a loop; generic arguments are dropped and a leading `::` is an empty first segment. A qualified path or a metavariable has no segments. |
| `src/extract/rs_macro_bind.rs` | The names a Rust macro invocation's token trees may bind (`tree_names`): identifiers outside a call or path position, items, generic parameters and `use` names declared inside them, and whether they hold an `impl` or trait. `narrow` gives the context the invocation's own calls are read in; possible names from every nested group reach the code around a statement or module-level invocation, and `is_statement` marks the former. | An uppercase name inside angle brackets or after a type-position token is a type, and a name opening a `field:` entry in a struct body is a field, not a binding. A lowercase name may declare an item. Can drop a call, never binds a local to an item. Trees are walked on an explicit stack. Invocation names are consulted alongside inherited scope sets without copying those sets per invocation. |

## Tests

Unit tests live beside the code they cover; integration tests under `tests/` drive the built
binary against `fixtures/`. `tests/conformance.rs` runs the public conformance suite;
`tests/semantic_audit.rs` and `tests/semantic_audit_direction.rs` score the resolver against the
committed oracle snapshots that CI also regenerates. Nothing in the suite reaches the network.
